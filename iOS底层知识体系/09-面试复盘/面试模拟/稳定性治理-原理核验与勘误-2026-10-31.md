## 1. 已核验：Jetsam 没有线程回溯，不等于没有系统报告

**原文位置**：基础版“补充 Q9：OOM 和 FOOM 的区别”，L442、L458–469；高级版“Q3：FOOM”，L84，“Jetsam 类终止通常没有”异常现场。

**风险表述**：把 OOM 统一解释为“超过系统限制被 Jetsam 杀掉”，或将“SDK 没有现场”扩展为“系统也没有可用报告”。这些说法不能替代具体终止证据。

**已确认的修正**：Apple 明确说明 Jetsam event report 是系统生成的报告，含设备中进程的内存信息，但**不包含应用线程回溯**。应检查报告中被终止的进程及其 `reason`，不能仅凭报告存在就认定本应用因内存压力退出。文档区分 `per-process-limit` 与 `vm-pageshortage` 等原因，不能把 Jetsam 一律简化为本应用越过单进程限制。来源：[S1]。

**建议补充措辞**：“Jetsam 可能有系统事件报告，但不同于带线程栈的普通 Crash report；归因须匹配被终止进程与 reason。”

**边界**：S1 不证明客户端 SDK 能在终止当刻执行回调，也不验证下一节的 SIGKILL/POSIX 规则或 FOOM 排除法准确率。

## 2. 未核验：SIGKILL 与 FOOM 排除法的确定性

**原文位置**：基础版 L446–447、L458–469（SIGKILL）；L500–510（“所有 APM 的共同底层逻辑”“applicationWillTerminate 未被调用”“大概率是 FOOM”）；高级版 L82–86 已主动限定为疑似归因。

**本地观察／风险**：基础版将生命周期回调缺失写作“非用户主动退出”条件，但本次没有取得回调保证或退出原因证据。高级版的“不确定性”表述与该条件的确定性语气不一致。

**处理**：不宣布 SIGKILL 规则或排除法已核验。FOOM 条件代码仅列为**归因演示**；本次没有证据将它升级为单次退出的确证。尚缺 POSIX 的信号约束、Apple 的生命周期保证及可区分 Watchdog/主动退出的资料。S1 仅支持核对实际 Jetsam 报告，不支持排除法的准确率。

## 3. 未核验：异常链、全局吞消息与恢复能力

**原文位置**：基础版 L259–263、L948（“Mach → Signal → NSException”）；L951（通用代理吞消息）；防护体系“2.1 OC 异常捕获”L143–173、“消息转发”L674–694；高级版“Q4”L94–98。

**本地观察／风险**：防护示例为未知方法统一返回 `"v@:"` 并不调用原有 `forwardInvocation:`；高级版却明确拒绝全局吞消息。防护体系中的 uncaught handler 还构造 Foundation 对象、写文件，并预留上传步骤。这些都是代码事实，不是安全性保证。

**处理**：暂不将“三层必然依次转换”、通用签名的兼容性、异常后继续运行或上传的安全性写作已确认结论。保留高级版的限制性立场；以上代码仅作为**未验证演示**，不能据“没有立即崩溃”宣称业务状态已恢复。尚缺 Apple 的异常处理／方法签名资料与 KSCrash NSException 上游实现。

## 4. 未核验：Signal handler 的崩溃现场安全性

**本地观察／风险**：示例调用 `backtrace_symbols`、`printf` 或 Foundation 容器／`NSLog`；完整框架继续进入文件写入和待上传数组维护。崩溃 APM 示例还将不同输入信号统一改为 `SIGABRT` 重发。示例与基础版的安全约束存在待核对之处。

**处理**：未取得 POSIX async-signal-safe 清单或 KSCrash handler 正文，不能声称本次已证明每个调用的安全性。将该捕获链明确视为**教学示意而非生产实现**；线程现场、最小记录、终止语义和 SDK 共存均未完成验证。

## 7. 未核验：RunLoop 超时、误报及监控开销

**处理**：保留“疑似超时线索”而非已确定卡顿时长。RunLoop 正常休眠、mode、前后台状态、调试器影响及抓栈开销均未取得 Apple/WWDC 正文验证；不报告误报率、功耗或开销数值。仅列为**待验证监控示例**。
