## 2. UITableView：旧／新坐标与模型必须属于同一个更新计划

### 官方已确认

1. `performBatchUpdates(_:completion:)` 把插入、删除、reload、move 合为一组；数据源也必须反映这些变更。[S1]
2. 批次先处理删除，再处理插入；删除／reload 指向原表，插入指向结果表。不要把更新前路径与可变数组逐步删改后的路径混用。[S1][S2]
3. 方法调用的书写先后不改变上述处理顺序。[S2][S3]
4. `insertRows` 会随即向 delegate／data source 获取可见内容，因此不能等动画 completion 才更新新增数据源。[S1][S3]
5. completion 的 `finished` 表示动画是否正常完成，不是数据源一致性的验证结果。[S1]

### 数量不变量与成立前提

在**固定一个 section、无 section 增删、无跨 section move**的追加／删除场景，令旧行数为 N、删除数为 D、插入数为 I：

`N_after = N - D + I`

这是根据官方一致性契约得到的数量推导，不是 Apple 页面的逐字公式。[S1][S2] 数量一致仍不足以保证消息 ID、顺序和 index path 正确；涉及 section 或跨 section move 时不能直接套用该简式。

**成稿可用技术说明**：“我核对的是同一个更新计划里的旧快照、目标结果和数据源返回值，而不是简单交换 insertRows／deleteRows 的调用顺序。删除索引属于旧表，插入索引属于结果表；数据源的实际增减必须与声明的行操作一致。”[S1][S2][S3]

## 3. 文本：输入阶段、UTF-16 范围、grapheme 与附件不能混为一谈

### 官方已确认

- `markedTextRange` 是 `UITextRange?`，表示多阶段输入中暂存、待用户确认的 marked text；没有 marked text 时为 nil。它定义的是**输入阶段**。[S4]
- `NSString` 的长度、索引及字符串范围以 **UTF-16 单元**表示；`length` 不能直接代表屏幕上看到的字符长度。[S5][S6] 这是相关字符串 API 的坐标约定，不是所有 `NSRange` 用途的统一单位。
- 组合字符序列／grapheme cluster 是**用户感知字符边界**；`rangeOfComposedCharacterSequences(for:)` 可以将已有合法范围扩展至覆盖完整序列，但输入范围必须先落在当前接收字符串内。[S6][S7]
- `NSAttributedString.init(attachment:)` 用附件基字符构造富文本；这说明“实际附件替换”与“普通文本索引”需要分开检查。[S8]

### 项目字符串实现：主任务已核验，不再仅列为猜测

主任务提供的源码核验定位：`067046131d:Pods/GBDCommon/Sources/Extensions/String.swift`，L12–15；项目扩展 `length()` 返回 **`String.count`**。[M2] 因此不能仅因函数名叫 length，就把该实现当作 `NSString.length` 或默认其结果属于 UTF-16 单位。[S5][S6]

这是**主任务核验结果的明确转述**，本附录未重复执行 Git。已定位到项目实际实现，不再将“调用了哪一种 length”写成猜测；但具体调用点是否用它构造 Foundation range，以及是否造成某次异常，仍须以调用代码和现场为证。不能直接从实现差异跳到事故确诊。
